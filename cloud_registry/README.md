# ☁️ Akili Cloud Registry

This module turns the curriculum into what a student device downloads: vectorised
course files, system prompts, and a manifest describing both. It is the source of
truth for every Akili instance.

---

## 🏗️ Structure

*   **`config/curriculum.yaml`** the master list of classes and subjects to process.
*   **`courses/`** source Markdown organised by grade and subject, plus the
    dynamic system prompts.
*   **`pipeline/`**
    *   `batch_pipeline.py` the main entry point. Reads the Markdown, embeds it,
        writes Parquet, exports prompts, generates the manifest, and optionally
        uploads everything to GCS.
    *   `manifest_generator.py` regenerates `manifest.json` alone.
    *   `prompt_exporter.py` exports the prompts alone.
*   **`registry/`** build output, and a local mirror of the bucket. Generated by
    the pipeline and **not tracked in git**: the distribution channel is GCS.

---

## ⚠️ The embedding model is shared with the client

This is the one thing to understand before running anything here.

The pipeline and the student device **must embed with the same model**. Query
vectors and document vectors are only comparable inside one vector space; a
mismatch does not raise an error, it returns noise ranked as though it were
relevant.

Both sides therefore read the same module, **`embedding_config.py` at the repo
root**. Never declare a model id in this folder, that is exactly how the registry
once got published at 3072 dimensions while devices queried at 384.

The manifest carries the stamp, so a device can refuse a registry it cannot search:

```json
"embedding": {
  "model": "sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2",
  "dim": 384
}
```

**Changing the model means republishing the whole registry**, and every device
re-fetching its courses and running `scripts/migrate_embeddings.py --apply`.
Treat it as a migration, not a setting change.

## 🛠️ Usage

### 1. Fetch the embedding model

The pipeline embeds locally, it does not call an embedding API. The ONNX model
has to be present:

```bash
uv run python scripts/fetch_embedding_model.py
```

### 2. Configure the curriculum

Edit `config/curriculum.yaml` to define your grades and subjects
(e.g. `math`, `history`, `english`).

### 3. Run the full pipeline

Builds everything and uploads to your GCS bucket:

```bash
uv run python cloud_registry/pipeline/batch_pipeline.py --upload
```

Drop `--upload` to build locally without publishing, which is useful for inspecting
`registry/` before it reaches any device.

The pipeline refuses to publish if the embedder produces a width other than
`EMBEDDING_DIM`, rather than shipping a registry no client can search.

### 4. Regenerate the manifest only

If you added a file to the bucket by hand:

```bash
uv run python cloud_registry/pipeline/manifest_generator.py
```

## ⚙️ Requirements

*   **The ONNX embedding model** (252 MB / 240 MiB, step 1). Embeddings are
    computed on this machine; **no embedding API key is needed**.
*   **GCS permissions** to publish the manifest and Parquet files. Either
    Application Default Credentials:

    ```bash
    gcloud auth application-default login
    ```

    or `GOOGLE_APPLICATION_CREDENTIALS` pointing at a service-account file. The
    bucket is derived from `MANIFEST_URL` in `app_local/config/settings.py`.

Note that no LLM API key is required to build the registry. Inference keys are a
client-side concern.
